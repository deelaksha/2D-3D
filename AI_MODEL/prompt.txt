1. Overall Goal

Build a fully local AI-powered 3D model generation application.

IMPORTANT:

For the first version, DO NOT integrate an actual 3D-generation AI model.

Instead, build the complete application architecture using MOCK/PLACEHOLDER 3D-generation tools.

Later, the mock implementation will be replaced by a real local 3D AI model without changing the rest of the application.

2. Important Development Rules

Follow these rules throughout the project.

Rule 1 — Work incrementally

DO NOT attempt to implement the entire application in one step.

Work phase-by-phase.

After completing each phase:

Run tests.
Verify the implementation.
Explain what was changed.
Explain how to test it.
Fix any failures.
Only then move to the next phase.
Rule 2 — Never silently skip failures

If something fails:

investigate it
identify the root cause
fix it
rerun the tests

Do not simply work around failures without documenting them.

Rule 3 — Keep the architecture modular

The real 3D model must eventually be replaceable without rewriting:

frontend
API
agent
LLM integration
conversation state
tool interfaces

Use interfaces/abstract classes/protocols where appropriate.

Rule 4 — No cloud dependency for the core AI

The LLM must run locally.

Do not make OpenAI, Anthropic, Gemini, or another paid cloud API a required dependency.

We will use a free local LLM.

Rule 5 — Do not integrate the real 3D model yet

Use mock implementations.

Create clean interfaces so that the real model can later replace the mocks.

Rule 6 — Keep secrets out of source code

Use environment variables/configuration files where required.

Never hard-code API keys, passwords, tokens, or credentials.

Rule 7 — Prefer simple engineering

Do not over-engineer the first version.

Build a working MVP first.

7. Phase 4 — Structured 3D Specification

The LLM should NOT directly generate arbitrary tool commands.

Instead, convert natural language into a structured specification.

Example user input:

"Create a futuristic black and red gaming chair with metal legs."

Expected structured output:

{
  "object": "gaming chair",
  "style": "futuristic",
  "materials": [
    "leather",
    "metal"
  ],
  "colors": [
    "black",
    "red"
  ],
  "parts": [
    "seat",
    "backrest",
    "armrests",
    "metal legs"
  ],
  "complexity": "medium"
}

Define Pydantic schemas for this.

The LLM output must be validated.

If invalid:

Detect invalid output.
Retry or repair the response.
Validate again.
Fail gracefully if still invalid.

Create tests for valid and invalid LLM outputs.

8. Phase 5 — Mock 3D Generator

Create the first 3D tool:

generate_3d(...)

DO NOT use a real AI model.

Implement a mock generator.

It should accept the structured 3D specification and return something like:

{
  "success": true,
  "model_id": "model_001",
  "status": "generated",
  "file_path": "outputs/model_001/model.glb"
}

The mock implementation may generate:

a placeholder GLB
a simple primitive
or a generated test asset

The important part is that it behaves like a real 3D generation service.

The rest of the application must not know that it is a mock.

Create an interface such as:

class ThreeDGenerator:
    def generate(...):
        ...

Then:

class MockThreeDGenerator(ThreeDGenerator):
    ...

Later we will implement:

class RealThreeDGenerator(ThreeDGenerator):
    ...
