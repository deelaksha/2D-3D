# Master Specification & Training Data Expansion Roadmap (2D-to-3D AI System)

## Executive Summary

This master document defines the complete technical architecture, dataset scaling strategy, fine-tuning execution pipeline, and Ollama deployment workflow for the local 2D-to-3D AI generation system.

The end-to-end system consists of:
1. **Multi-Modal Vision Understanding (`qwen2.5vl:7b`)**: Reads uploaded 2D images, photos, sketches, and floor plans to perform spatial, material, bounding box, and part decomposition.
2. **Text Agent & Spec Synthesizer (`qwen3:8b` / fine-tuned model)**: Translates visual extractions into structured 3D specifications (`ThreeDSpecification`) and tool execution plans.
3. **Procedural 3D Mesh Engine**: Synthesizes watertight 3D meshes (GLB/OBJ/FBX), interlocking woodkit joints, and 2D printable panel layouts.
4. **Training & Fine-Tuning Subsystem (`house-3d-training-data`)**: Generates ground-truth synthetic data via Blender, formats JSONL training sets, executes QLoRA fine-tuning, and exports custom GGUF models for Ollama.

# 2. MASSIVE DATASET GENERATION & SCALING ROADMAP

To reach state-of-the-art accuracy in 2D-to-3D understanding, training data generation scales across 4 distinct dataset tiers:

```text
Phase 1:  1,000 Samples  -> Initial validation of generator scripts & baseline metrics
Phase 2: 10,000 Samples  -> Component-level variation & room-scale spatial assemblies
Phase 3: 50,000 Samples  -> Full architectural buildings, multi-view renders & depth maps
Phase 4: 100,000+ Samples-> Massive domain coverage (houses, furniture, industrial parts)
```

## Dataset Distribution Target (First 10,000 Samples)
- **20% Walls**: External, internal, partition, load-bearing, and curved walls.
- **15% Doors**: Single, double, sliding, folding, glass, and garage doors.
- **15% Windows**: Single, double, sliding, casement, bay, and arched windows.
- **10% Floors & Slabs**: Single-story and multi-level floor assemblies.
- **10% Roofs**: Pitched, flat, gabled, hip, and mansard roofs with eaves & ridges.
- **5% Staircases & Railings**: Straight, L-shaped, spiral stairs, and balconies.
- **5% Columns & Beams**: Structural support posts, pillars, and joists.
- **5% Interior Furniture**: Tables, chairs, desks, cabinets, and shelving units.
- **15% Full Assemblies**: Complete multi-room houses, villas, and apartments.

# 3. PARAMETRIC SYNTHETIC GENERATION (BLENDER PIPELINE)

Ground-truth synthetic samples are generated programmatically in Blender to guarantee 100% exact annotations.

For every generated sample `sample_XXXXXX/`, the pipeline outputs:
- **`image.png`**: High-resolution RGB render (canonical view).
- **`views/`**: Multi-view RGB renders (`front.png`, `side.png`, `top.png`, `iso.png`).
- **`depth.exr`**: Lossless camera-distance EXR depth map.
- **`segmentation.png`**: Semantic and instance segmentation mask.
- **`mesh.glb`**: Watertight, manifold ground-truth 3D mesh.
- **`scene.json`**: Hierarchical scene graph detailing components, bounding boxes, transforms, materials, and parent-child relationships.
- **`camera.json`**: Exact intrinsic matrix ($K$), extrinsic transform ($R, t$), FOV, and clip planes.

# 4. DATA AUGMENTATION & FORMATTING PIPELINE

To make fine-tuned models robust against noisy real-world images, synthetic datasets undergo automated augmentations before training:

## Image-Level Augmentations
- **Lighting & Color**: Random gamma variations ($\gamma \in [0.8, 1.2]$), contrast jittering, exposure shift.
- **Camera Noise**: Gaussian sensor noise, subtle motion blur, resolution downscaling ($512\times512 \rightarrow 256\times256 \rightarrow 512\times512$).
- **Geometric Distortion**: Perspective tilt ($\pm 10^\circ$), minor random cropping ($5\%$), lens distortion.

## Formatting for Qwen SFT (`qwen_formatter.py`)
Samples are serialized into JSONL instruction pairs:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "<image>\nAnalyze this architectural image and extract 3D parametric components, dimensions, and relationships."
    },
    {
      "role": "assistant",
      "content": "{\n  \"object\": \"house\",\n  \"style\": \"modern_architectural\",\n  \"dimensions\": {\"width\": 8.5, \"height\": 6.2, \"depth\": 10.0},\n  \"components\": [\n    {\n      \"id\": "ext_wall_01\",\n      \"type\": \"external_wall\",\n      \"dimensions\": [8.5, 3.2, 0.25],\n      \"transform\": {\"position\": [0, 0, 1.6], \"rotation\": [0, 0, 0]},\n      \"material\": \"concrete\",\n      \"color\": \"white\"\n    },\n    {\n      \"id\": \"front_door_01\",\n      \"type\": \"single_door\",\n      \"dimensions\": [1.0, 2.1, 0.1],\n      \"transform\": {\"position\": [1.2, 0, 1.05], \"rotation\": [0, 0, 0]},\n      \"material\": \"wood\",\n      \"color\": \"oak\"\n    }\n  ],\n  \"relationships\": [\n    {\"source\": \"front_door_01\", \"relation\": \"inserted_into\", \"target\": \"ext_wall_01\"}\n  ]\n}"
    }
  ]
}
```

# 5. QLoRA FINE-TUNING EXECUTION PIPELINE (`train_qwen.py`)

Fine-tuning is executed using QLoRA (Quantized Low-Rank Adaptation) to optimize parameter efficiency on local GPU hardware.

## Fine-Tuning Setup & Hyperparameters
- **Base Model**: `Qwen/Qwen2.5-Coder-7B-Instruct` or `Qwen/Qwen2.5-VL-7B-Instruct`
- **Quantization**: 4-bit NormalFloat (`nf4`) with double quantization enabled.
- **Compute Precision**: `bfloat16` (or `fp16` on legacy GPUs).
- **LoRA Configuration**:
  - Rank ($r$): `16`
  - Alpha ($\alpha$): `32`
  - Dropout: `0.05`
  - Target Modules: `["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]`
- **Training Parameters**:
  - Learning Rate: `2e-4` with cosine decay.
  - Per-Device Batch Size: `2`
  - Gradient Accumulation Steps: `4` (Effective batch size = 8)
  - Epochs: `3`
  - Optimizer: `paged_adamw_8bit`

## Training Command Execution
```bash
# Dry-run validation check
python house-3d-training-data/training/train_qwen.py --dry_run

# Full GPU Training Run
python house-3d-training-data/training/train_qwen.py \
    --base_model Qwen/Qwen2.5-Coder-7B-Instruct \
    --dataset_path house-3d-training-data/datasets/house/processed/qwen_reasoning_train.jsonl \
    --output_dir house-3d-training-data/training/checkpoints/qwen_house_3d \
    --epochs 3 \
    --batch_size 2 \
    --learning_rate 2e-4
```

# 6. OLLAMA MODEL EXPORT & DEPLOYMENT PIPELINE

Once training completes, the fine-tuned adapter is merged and exported to Ollama for local inference.

## Step 1: Merge & Export GGUF Modelfile
Run `export_ollama_modelfile.py` to create the Ollama Modelfile manifest:

```bash
python house-3d-training-data/training/export_ollama_modelfile.py \
    --checkpoint_dir house-3d-training-data/training/checkpoints/qwen_house_3d/final_adapter \
    --output_modelfile Modelfile.qwen-house-3d \
    --model_name qwen-house-3d
```

## Step 2: Register & Run Model in Ollama
```bash
# Create Ollama local model instance
ollama create qwen-house-3d -f Modelfile.qwen-house-3d

# Test fine-tuned model via CLI
ollama run qwen-house-3d "Create a 3D low-poly wooden house with 2 windows and 1 door"
```

# 7. AUTOMATED QUALITY BENCHMARKING & METRICS

Before deploying new model checkpoints, the evaluation framework calculates quantitative metrics across held-out test splits:

| Metric | Target Threshold | Description |
|---|---|---|
| **Component Identification Accuracy** | $\ge 95\%$ | Precision/Recall for identifying walls, doors, windows, and roof types. |
| **Dimension Bounding Box IoU** | $\ge 90\%$ | 3D Intersection-over-Union between estimated vs ground-truth bounding boxes. |
| **Spatial Relationship Accuracy** | $\ge 92\%$ | Accuracy of parent-child attachment links (e.g. door inserted into wall). |
| **Mesh Validity & Manifold Rate** | $100\%$ | Percentage of generated meshes passing watertight manifold verification. |
