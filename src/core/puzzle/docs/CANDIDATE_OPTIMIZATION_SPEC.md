# Candidate Optimization Integration Specification (Phase 54)

This document specifies the **Candidate Optimization Integration Subsystem & Multi-Objective Scoring Engine** for evaluating 9 quality sub-metrics, applying configurable objective weights, ranking candidate designs, and selecting optimal valid candidates.

---

## 1. Architectural Mandate & Invalid Candidate Exclusion Invariant

> [!IMPORTANT]
> **OPTIMIZER NEVER SELECTS AN INVALID CANDIDATE**:
> - **Strict Validity Gate**: The candidate optimizer evaluates candidates generated by the multi-candidate generator. Any candidate marked with `validationResult.status === "REJECTED"` is assigned `isValidCandidate: false` and is **strictly excluded from `bestCandidate` selection**, regardless of its total weighted score.
> - **All 9 Sub-Metrics Evaluated**:
>   1. `materialUtilization`
>   2. `connectionQuality`
>   3. `assemblyDifficulty`
>   4. `pieceCountEfficiency`
>   5. `geometricComplexity`
>   6. `manufacturability`
>   7. `clearanceQuality`
>   8. `symmetry`
>   9. `assemblyQuality`
> - **Zero Model Training**: Implements the multi-objective candidate optimizer, scoring breakdown, and ranking engine; zero model training is performed.

---

## 2. Configurable Weights & Multi-Objective Formula

$$\text{TotalWeightedScore} = \sum_{i=1}^9 w_i \cdot S_i \quad \text{where } \sum_{i=1}^9 w_i = 1.0$$

```typescript
export interface OptimizationObjectiveWeights {
  materialUtilization: number;     // Default 0.15
  connectionQuality: number;       // Default 0.15
  assemblyDifficulty: number;      // Default 0.10
  pieceCountEfficiency: number;   // Default 0.10
  geometricComplexity: number;    // Default 0.10
  manufacturability: number;       // Default 0.15
  clearanceQuality: number;        // Default 0.10
  symmetry: number;                // Default 0.05
  assemblyQuality: number;         // Default 0.10
}
```

## 3. Future RL & Evolutionary ML Optimization Integration Roadmap

In future ML phases, Reinforcement Learning (PPO/SAC) or Evolutionary Genetic Algorithms (NSGA-II) will optimize candidate design spaces without replacing the deterministic validation engine:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                   FUTURE RL & EVOLUTIONARY OPTIMIZATION ROADMAP                        │
└────────────────────────────────────────────────────────────────────────────────────────┘

  1. Reinforcement Learning (RL) • Reward Function R = TotalWeightedScore * (isValid ? 1 : 0)
                                 • Agent (PPO/SAC) mutates parametric specification variables.
                                 • Deterministic validation engine provides immediate reward/penalty.

  2. Genetic Algorithms (NSGA-II) • Population of Candidate Specifications.
                                 • Crossover & Mutation operators mutate tab/slot dimensions.
                                 • Pareto-frontier optimization over Manufacturability vs Aesthetics.

  3. Deterministic Invariant    • Under all ML/RL regimes, AIDesignValidationGate retains
                                   100% veto authority over candidate selection.
```

## 4. Programmatic API Usage

```typescript
import { CandidateOptimizer } from "@/core/puzzle/candidateoptimization";
import { DeterministicCandidateGenerator } from "@/core/puzzle/multicandidate";

// 1. Generate multi-candidate design options
const generator = new DeterministicCandidateGenerator();
const comparison = await generator.generateCandidates("Create a 12-piece puzzle.", 5);

// 2. Optimize and rank candidates with custom objective weights
const report = CandidateOptimizer.optimizeCandidates(comparison.candidates, {
  manufacturability: 0.40,
  materialUtilization: 0.30,
});

console.log(`Top Valid Candidate: ${report.bestCandidate?.candidateLabel}`);
console.log(`Weighted Score: ${report.bestCandidate?.scoreBreakdown.totalWeightedScore}`);
```
